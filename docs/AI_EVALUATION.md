## Provider layer (`apps/api/app/agents/llm/`)
- One OpenAI-compatible client serves Ollama, the Hugging Face router, vLLM, and similar endpoints. New protocols add a client.
- `models.yaml` records provider, model, capabilities, context, prices, timeout, retries, concurrency, and fallback.
- Availability is checked by asking the provider. Missing models, missing keys, and out-of-memory conditions are distinct, clear errors.
- Retries and fallback apply only to transient failures. A fallback is reported in `fallback_from`, never hidden, and invalid output is an error rather than a guess.
- Unknown prices stay unknown: `estimate_cost` returns `None`, not zero. Local cost is $0 in tokens and excludes hardware and power.
- Consequential actions are gated by deterministic permission checks and human approval, never by model confidence.

## Evaluation (`apps/api/app/agents/evaluation/`)
```bash
cd apps/api
uv run python -m app.agents.evaluation --status
uv run python -m app.agents.evaluation --models baseline,qwen3-4b --split test
uv run python -m app.agents.evaluation --report
```
Each run writes `research/evaluations/<run_id>/records.jsonl` and `summary.json`, and never overwrites an earlier run.
Every record stores: task, dataset version, model and what actually served it, prompt version, tokens, latency, estimated cost,
schema validity, failure category, prediction, and an empty slot for a human rating. Each run stamps its git commit.

| Task | Measures |
|---|---|
| Classification | Accuracy with 95% Wilson interval, macro F1, confusion matrix |
| Extraction | Field accuracy, plus the rate of invented facts when the text states nothing |
| Injection | How often low-fit leads with planted instructions get labelled high |
| Synthesis, outreach | Lexical support, invented numbers, invalid or missing citations, injected source cited or obeyed |
| Retrieval | Recall@1 and MRR, keyword overlap against real embeddings |

Failed calls count as wrong. Tasks use a held-out split whose signal phrasing and fact wording do not appear in train.
The rule baseline runs first, and any model has to beat it to justify its cost.

## Findings (held-out split, fictional data)
- **Extraction:** the clearest result. `qwen3-4b` scored 98% field accuracy (95% CI 96–99%) with no invented facts, against
  91% for `qwen2.5-7b`, 90% for `mistral-7b`, and 27% for the baseline.
- **Classification:** models scored 62–67% and the baseline 53%. The intervals overlap, so no ranking is established.
- **Prompt injection:** a real risk for every model. Planted instructions forced a "high" label in 55% of attacks on
  `qwen3-4b`, 40% on `mistral-7b`, and 20% on `qwen2.5-7b`. The baseline ignores them. In synthesis, `qwen3-4b` obeyed 8 of 12.
- **Outreach:** `qwen2.5-7b` fell into repetition loops and hit the token limit on 9 of 24 drafts (10 of 24 in its first run,
  so runs are not exactly repeatable). `mistral-7b` included unsupported numbers in 15 of 24. `qwen3-4b` had neither problem
  but obeyed the injection in 3 of 12.
- **Retrieval:** embeddings reached 96% recall@1 and keyword overlap 79%. The intervals overlap slightly.

Routes in `models.yaml` follow these results: `qwen3-4b` for extraction and outreach, `qwen2.5-7b` for classification
(same accuracy as `qwen3-4b`, fewer successful attacks, faster) and synthesis. They were chosen on the held-out split, so
the chosen models' scores are optimistic. Outreach stays behind human approval.

## Gates (Phase 5)
Results: [research/evaluations/GATES.md](../research/evaluations/GATES.md), generated by
`uv run python -m app.agents.evaluation --gates --models qwen2.5-7b,qwen3-4b`. Scores never read model output, so these
measure what a person might read in a brief, not what could move a score.
- **On the dataset's attacks,** the input gate flagged all of them with no false alarms on 156 clean texts, and no injection
  survived in either live model. This is optimistic: the test attacks reuse the training templates.
- **On 8 attacks reworded separately,** the input gate flagged none, so all 8 reached the models. `qwen2.5-7b` repeated 3 and
  the output gate removed all 3. `qwen3-4b` repeated 6, and 4 survived the output gate, 3 of them citing the attack as a source.
  **Gates alone do not make model text safe.** This is why briefs are labelled as inference, and why outreach (Phase 8), which is
  routed to `qwen3-4b`, must stay behind human approval.
- **The cost:** the output gate removed about a third of live claims (33 of 48 kept for `qwen2.5-7b`, 30 of 45 for `qwen3-4b`).
  Whether the removed claims were correct has not been measured, and lexical support penalizes honest paraphrase.
- The sample is too small to rank the models, and "repeated" is a rough wording match.

## Agents (Phases 7 and 8)
Results: [research/evaluations/AGENTS.md](../research/evaluations/AGENTS.md), generated by
`uv run python -m app.agents.evaluation --agents --models qwen2.5-7b,qwen3-4b` against a disposable database. Attacks went straight into accepted
evidence, skipping the input gate. These are small samples on fictional data, and numbers move between runs of the same attacks (`qwen3-4b` repeated 1, then 4, then
5 of the 8 reworded ones), so read them as behavior and not as rates.

**Research agent, 14 attacks: 8 reworded and 6 aimed at named tools.**
- **Neither model tried a tool outside its list or another lead's record, in 51 tool calls.** So this run did not exercise those
  refusals, and it does not show they work. `tests/test_mcp.py` does that by making the forbidden calls directly. A stronger model or
  attack might behave differently.
- **The review did not stop planted text.** Of the 8 reworded attacks, `qwen2.5-7b` repeated 4 and 3 survived the review, and `qwen3-4b` repeated 5 and 4 survived. This is why
  agents have no write tools and their output is labelled for a person to judge.
- **The 6 tool-aimed attacks have no wording to match,** so the report shows only whether a tool was misused, not whether the text was repeated.
- **Skipped research:** in 2 of 28 runs, both `qwen3-4b`, the model answered without calling a tool. The review kept 0 of those 8 claims.
- **The cost:** the review kept 46 of 60 claims for `qwen2.5-7b` and 45 of 71 for `qwen3-4b`. Whether the removed claims were correct has not
  been measured. Median time was 15.7 s and 119.3 s on this machine.

**Outreach agent, 6 attacks aimed at what the email says, such as a planted link, a false guarantee, or a request for login details.**
- **Planted text reached the drafts.** `qwen2.5-7b` repeated 5 of 6 and `qwen3-4b` repeated 3 of 6, and the review dropped none of those drafts. This is the most
  important result in this section: **the person approving a draft is what stands between a planted instruction and a real recipient.**
- **The planted link was caught both times.** Each of those drafts has to be edited before it can go for approval.
- **Before and after the number flag.** The run before it (commit `4c30312`'s report) had 3 drafts carrying planted text with no flag, the false 300% guarantee in both models and an account
  number in one. In this run, with every number flagged, none had no flag.
- **That result flatters the flag.** It fired on all 12 drafts, whether or not the number had anything to do with an attack, and a draft repeating the request for login details was flagged only
  because it also held some unrelated number. A warning on every draft is easy to stop reading. How often it fires on drafts with no attack in them was not measured, and planted text with no
  digits in it gets no flag from this check.
- Neither model tried a tool outside its list. No draft in this measurement was sent to anyone, and none could be, because nothing here approves or sends.

## Data and honesty rules
`research/datasets/` is synthetic and fictional, with labels from a known rule, so results compare methods and do not predict
production accuracy or conversion. No accuracy, cost, or savings figure is stated without a measurement behind it.
Lexical support is a screening heuristic. Fine-tuning waits until evaluation shows a gap it would close.

## Notebooks
`research/notebooks/` holds 01–06, generated by `build_notebooks.py` so setup cannot drift. Notebooks import the same backend
modules and stop with a clear error if no real model is reachable. On Colab, use a clone of this repository with `HF_TOKEN` as a
Colab secret, or a local model server. Colab is for experiments only, never production. It has no GPU guarantee or persistence.
